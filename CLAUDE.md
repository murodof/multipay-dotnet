# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this service is

`PaymentService` is the backend of an iframe checkout that tops up a mobile balance with an
Uzcard/Humo card. It is a **port** of the Python/FastAPI service in `../multipay` to .NET 10,
ASP.NET Core, EF Core and MS SQL Server. The port is deliberately not a redesign: layering, HTTP
contract, order of checks, state machines and security rules are the Python service's; only the
language and the stack changed. Frontend and Operator talk to this service exactly as they talk to
the Python one — URLs, JSON keys and key order, HTTP statuses, `error_code` numbers and headers are
pinned by tests, several of them byte-for-byte against output captured from the Python service.

An **Operator** site embeds `https://pay.<domain>.uz/?hash=<signed hash>`; the frontend posts that
hash to `POST /api/uzcard/session` or `POST /api/humo/session`. That authenticates it and opens a
short-lived session bound to that provider. Uzcard card entry, OTP, payment, recovery, Operator
credit, reverse and receipt flows are implemented; HUMO's MW/SMS/SOAP flow is implemented behind
`HUMO_ENABLED`, which defaults to false pending a real test environment and merchant credentials.

The port tracks the Python repository up to commit `3341e09` (2026-10-09). Later Python commits
have to be carried over by hand: diff `app/` from that commit and port each behaviour change with
its test.

When a rule below says "same as Python", the reason is in `../multipay/CLAUDE.md` and is repeated
here only where the .NET shape differs. **Read "Differences from the Python service" before "fixing"
anything back to idiomatic ASP.NET** — most of the non-idiomatic code exists to keep the contract.

## Layering and dependency injection

```
src/PaymentService/
  Api/Controllers/                    thin actions: model-bound guard + body, one service call
  Infrastructure/Services/            provider orchestration and use cases; return envelopes
  Infrastructure/Repositories/        EF Core access; each repo commits its own writes
  Infrastructure/ExternalServices/    Redis, SV-GATE (Uzcard/), HUMO MW/SMS/PS (Humo/), Operator
  Infrastructure/Utils/               pure helpers: operator hash, phone, money, card, Py semantics
  Domain/{Models,Schemas,Enums}/
  Core/{Configurations,Handlers,Middlewares,Dependencies}/
  Migrations/                         generated by dotnet-ef
  Program.cs                          the composition root
```

File and class names mirror the Python modules (`uzcard_service.py` → `UzcardService.cs`,
`payment_session_repo.py` → `PaymentSessionRepository.cs`) so the two code bases can be read side
by side.

Python's `inject()` convention does not exist here: .NET has a container, so classes take their
dependencies through constructors and `Program.cs` registers them. What survives is the rule
behind it — a controller action receives only the service (plus the session guard through model
binding) and makes one call; services receive repositories and clients; `PaymentDbContext` is
scoped (one per request, shared by all repositories of that request, exactly like the request's
`AsyncSession`); `RedisClient` is a singleton. `TestArchitecture` checks that every
`*Service`/`*Repository`/`*Client` is resolvable and that controllers depend on neither
repositories, clients nor EF Core.

The two payment flows are registered as keyed `IPaymentFlow` services (`ProcessingSystem.UZCARD`,
`ProcessingSystem.HUMO`); `UzcardController` and `HumoController` share their actions through the
abstract `ProviderController`, the equivalent of `router_provider.payment_router()`. The
`[Provider(...)]` attribute on each controller tells the guard which provider the route belongs to.

Services, repositories and utils never `throw` (enforced with Roslyn). Results travel as
`BaseResponse` envelopes or `null`. Redis and SQL errors are **not** caught: a request that cannot
claim its nonce fails with 500 rather than opening a session unchecked (fail closed).

## Response envelope

```
HTTP 200  {"success":true,"result":{...}}
HTTP 4xx  {"success":false,"error":{"code":"HASH_EXPIRED","error_code":-2002,
                                     "message":{"uz":...,"en":...,"ru":...},"details":{...}}}
```

`StatusCodes` (a class, not an enum, because each member carries a name, number, HTTP status and
three messages) is generated verbatim from `status_codes.py`: 35 members, `-2000 … -2034`.
`BaseResponse` implements `IActionResult`, so an action that returns it sets the status, the
`Retry-After` header (from `details.retry_after`) and writes the body itself.

The body is written by hand rather than through MVC output formatters because the bytes must match
FastAPI's `JSONResponse`: `Content-Type: application/json` (no `charset`), compact separators,
raw UTF-8 (`PythonJsonEncoder` escapes only `"`, `\` and control characters, like
`json.dumps(ensure_ascii=False)`), `null` fields kept, snake_case keys in declaration order, and
datetimes as pydantic prints them (`2026-10-02T13:00:00Z`, microseconds only when non-zero).

FastAPI's own failures are reproduced:
- body binding failures (not JSON, wrong type, missing body, non-JSON content type) → 422
  `INVALID_REQUEST` through `ApiBehaviorOptions.InvalidModelStateResponseFactory`; a body that is
  not valid UTF-8 → 400 with `UNKNOWN_ERROR`, as FastAPI's "error parsing the body";
- 404 / 405 → `NOT_FOUND` / `METHOD_NOT_ALLOWED` envelopes through `UseStatusCodePages`; 405 keeps
  its `Allow` header;
- unhandled exceptions → logged with the stack trace, open idempotency claims released, 500
  `UNKNOWN_ERROR` without details. ProblemDetails is never produced.

`hash` is optional in `SessionCreateSchema` on purpose so a missing one is `HASH_INVALID` in the
envelope, not a 422. Schemas validate themselves from a `JsonElement` (`IRequestSchema<T>.Validate`)
with pydantic's lax rules (`payment_confirmed` accepts `"yes"`, `1`, `1.0`; `expiry` digits are
Unicode `isdigit()`), because automatic deserialization into typed models cannot express them.

## `POST /api/{provider}/session` — the order of checks is the design

`SessionService.Create`, unchanged from Python, returns at the first failure:
IP rate limit → MAC → timestamp → phone rate limit → nonce → order → phone → amount. Each
position's reason is in `../multipay/CLAUDE.md` and each is pinned by a test in `TestSession*` /
`TestRateLimiting` (mutation-checked: break the guard, watch that test fail). The clock is read
once at the top.

The unique index on `order_id` is the idempotency guarantee; `PaymentSessionRepository.Create`
turns SQL Server error **2601/2627 only** into `null` → `ORDER_EXISTS`. Any other
`DbUpdateException` propagates (500).

## Hash format

Identical to Python: `<kid>.<b64url(payload)>.<b64url(HMAC-SHA256(secret[kid], "<kid>.<b64url(payload)>"))>`,
strict canonical base64url, max 2048 chars, dummy-key HMAC and a single
`CryptographicOperations.FixedTimeEquals` for unknown/expired kids. `amount` and `ts` must be JSON
integer literals (no `.`/`e`, never bool or string) — checked on the raw token text, with
`BigInteger` so `10**20` is "an integer, out of range" as in Python. `order_id`'s limit is read from
the EF model's `MaxLength` (`PaymentSessionRepository.OrderIdLength`), not restated.
`OperatorHash.SignHash` is the Operator-side reference implementation; tests prove that hashes
signed by the Python `sign_hash()` verify identically here and that both produce the same bytes
(`Fixtures/python_signed_hashes.json`).

Because C# cannot monkeypatch `FixedTimeEquals`, the "compared in constant time" tests read
`VerifyHash`'s syntax tree: one comparison, no return between the key lookup and it, and `!usable`
evaluated after it.

### Key rotation

`SECRET_KEYS=kid:secret[@expiry]`, comma separated, parsed per request (`SigningKeys.Parse`) and once
at start-up through options validation. **Every** error names the entry position, never the kid —
see the differences section for why this is stricter than the Python code.

## Session token

`Defaults.TokenUrlSafe(16)` (128 bits, 22 base64url chars), returned once; only its SHA-256 is
stored. No cookie on the API. `SessionGuard.Inject` is a scoped service invoked by
`SessionAccessBinder`, the model binder that plays FastAPI's `Depends(SessionGuard.inject)`:
`Bearer` prefix, non-empty token, `id` + token-hash lookup, then the provider check.

## Time

`TimeProvider` is injected everywhere `get_utc_now()` was used; `Defaults.UtcNow(clock)` truncates
to microseconds so in-memory values equal what `datetimeoffset(6)` stores (Postgres also keeps µs).
`created_at`/`updated_at` are set in `PaymentDbContext.SaveChangesAsync` from the same clock
(SQLAlchemy's `default`/`onupdate`); an explicitly modified `UpdatedAt` is kept. Tests replace the
clock with `FakeTimeProvider` started at "now" truncated to the second (`FrozenClock`). Unlike the
Python suite, which froze only the service modules, the fake clock also drives timestamps and the
recovery workers — tests set ages through the clock instead of real time.

## Persistence

- Tables and columns are snake_case (`payment_sessions.session_token_hash`) through a naming loop in
  `OnModelCreating`; the property names stay PascalCase.
- UUID → `uniqueidentifier` (generated client-side with `Guid.NewGuid()`, i.e. uuid4, not EF's
  sequential GUIDs, so receipt numbers keep their 8 random hex characters); `BigInteger` → `bigint`;
  aware datetimes → `datetimeoffset(6)`; JSON → `nvarchar(max)` + `ISJSON(...) = 1` CHECK
  (`svgate_log.response_masked` also accepts a JSON scalar through `ISJSON('[' + col + ']')`,
  because `ISJSON` alone is true only for objects and arrays and a provider may answer `"text"`); enums →
  `nvarchar(20)` + the `status IN (...)` CHECK under the Python constraint names.
- **Every string column uses the `Latin1_General_100_BIN2` collation.** SQL Server's default
  collation is case-insensitive: `ORDER-1` would collide with `order-1` in the unique index and the
  status CHECK would accept `created`. BIN2 gives Postgres' byte-wise equality.
- The migration switches the database to `READ_COMMITTED_SNAPSHOT`, so plain reads behave like
  Postgres MVCC reads and do not block behind row locks.
- Money is `long` tiyin; commission uses `decimal` with `MidpointRounding.AwayFromZero`
  (`ROUND_HALF_UP`), and `total = amount + commission` is a CHECK constraint.

### `SELECT … FOR UPDATE` + `populate_existing=True`

Every state transition (`SetStatus`, `TransitionPaying`, `BeginUzcardPay`, `RecordRecoveryFailure`,
`ClearCardToken`) runs in a transaction:

1. `SaveChanges` first — SQLAlchemy autoflushes pending changes before the locking query, and some
   callers rely on it (e.g. `card_attempts`, `check_attempts`).
2. `SELECT * … WITH (UPDLOCK, ROWLOCK)` via `FromSql`, **no tracking**, then the fresh values are
   copied onto the already-tracked entity (`Adopt`). EF, like SQLAlchemy's identity map, would
   otherwise hand back the tracked instance with stale values; copying (rather than detaching)
   keeps the object the controller holds identical to the one the service mutates.
3. Check the status, mutate, `SaveChanges`, commit, reload.
4. On a failed check, roll back and reload every tracked entity — SQLAlchemy's rollback expires all
   instances.

`Save()` is `SaveChanges` + reload (SQLAlchemy `commit` + `refresh`), so concurrent changes to
other columns become visible exactly when they did in Python. Recovery "claims" stay conditional
transitions; the Python code uses no `SKIP LOCKED`, so no `READPAST` appears either.

## Idempotency

Same as Python: UUID `Idempotency-Key`, `idem:<session>:<action>:<key>` holding an HMAC fingerprint
(keyed with `SECRET_KEYS`) of the validated body and an owner token, `IDEMPOTENCY_CONFLICT` for a
reused key with another body, completion with the compare-and-set Lua script. Python kept open
claims in a `ContextVar`; in .NET an `AsyncLocal` set inside the service would not flow back to the
exception middleware, so the open claims live in the scoped `IdempotencyClaims`, which
`UnhandledExceptionMiddleware` resolves from the request's services. Database transitions remain
the financial duplicate-execution guard.

## Rate limiting

One Lua script, sorted set per window, keys with hash tags (`rate:{ip:1.2.3.4}:1m`), refused hits
never recorded. The three Lua scripts are the Python ones verbatim modulo indentation
(`Lua_scripts_are_unchanged_from_python`).

### Client IP

`ForwardedHeadersMiddleware` is the only reader of `X-Forwarded-For`, with
`KnownProxies`/`KnownIPNetworks` built from `FORWARDED_ALLOW_IPS` (IPs, CIDRs, `*` as uvicorn
accepts) and `ForwardLimit = null` so the chain is walked right to left like uvicorn's
`ProxyHeadersMiddleware`. Never trust all proxies by default: a client would rotate the header and
reset its IP limit. IPv4-mapped IPv6 peers are reported as plain IPv4, as uvicorn does.

## Security headers, CORS and routing

Middleware order, outermost first: access log → `SecurityHeadersMiddleware` →
`UnhandledExceptionMiddleware` → `ApiCorsMiddleware` → forwarded headers → status-code envelopes →
`StarletteRoutingMiddleware` → routing/endpoints.

- Security headers are the Python set (CSP `frame-ancestors`, HSTS, `nosniff`, `no-referrer`,
  `Permissions-Policy`, `Cache-Control: no-store`, `Pragma`), with the docs and admin variants.
  Because the middleware is outermost, the 500 from an unhandled exception carries them too (and the
  CORS headers), as in Python since its `UnhandledErrorMiddleware`.
- `ApiCorsMiddleware` is a line-by-line port of Starlette's `CORSMiddleware` (preflight `200 "OK"`
  / `400 "Disallowed CORS origin"` plain text, sorted allow-headers including the safelisted ones,
  `Access-Control-Max-Age: 600`, `Vary: Origin`, `Access-Control-Expose-Headers: Retry-After` on
  simple requests). ASP.NET's CORS middleware answers differently (204, silent failures), so it is
  not used. CORS applies to `/api/*` only. A preflight asking for private-network access is refused
  (`Disallowed CORS private-network`). `ALLOWED_ORIGINS` accepts `https://host[:port]` (optionally
  `*.`) because the value is pasted into a header; `*` and `http://localhost[:port]` are accepted
  for local frontends and refused when `ENVIRONMENT=production`. A configured `*` is answered as
  Starlette does: a literal `Access-Control-Allow-Origin: *` without `Vary: Origin`.
- `StarletteRoutingMiddleware` restores two Starlette behaviours ASP.NET routing lacks: paths are
  case-sensitive (`/API/...` is 404), and a trailing-slash miss is redirected with `307` to the
  slashless route (`Location: scheme://host/path?query`, percent-encoded like Starlette's
  `RedirectResponse`, empty body).
- Kestrel's `Server` header is off. uvicorn sends `server: uvicorn` by default; nothing here
  imitates it (see known gaps).

## Logging

Serilog writes stdout and a size-rolled file (`LOG_MAX_BYTES`, `LOG_BACKUP_COUNT` backups,
`LOG_FILE=` disables it) through `QueryStringMaskingFormatter`. The formatter renders the message
first and masks every query value in the **rendered** text — the lesson of the Python `%s`
incident (masking the template turned `?hash=%s` into `?hash=***`, formatting failed and logging
printed the raw argument to stderr). Exception text is masked as well. Lines look like Python's
`%(asctime)s %(levelname)s %(name)s: %(message)s`. `AccessLogMiddleware` writes uvicorn-style
access lines (`ip:port - "GET /path?q=*** HTTP/1.1" 200`) through the same formatter; Microsoft's
own request logs are raised to Warning so the URL is not logged twice.

## Migrations

There is one initial EF migration built from the current models, not a port of the five Alembic
revisions. `scripts/regenerate_initial_migration.sh` recreates it (and re-adds the RCSI
statement) while the service has no production database. Tests build the schema with
`Database.MigrateAsync()` and assert `HasPendingModelChanges()` is false, so a model edit without a
migration fails the suite. The Docker image ships an `efbundle` (`./migrate`) that the compose
command runs before the app.

## Tests

- **Real SQL Server** (`Testcontainers.MsSql`, 2022) and **real Redis** (`Testcontainers.Redis`) —
  idempotency rests on a unique index under concurrent inserts and the sliding window is a Lua
  script; no in-memory substitute runs either.
- One container pair per test run (`AppCollection`); each test truncates the tables, flushes Redis
  and builds its own `WebApplicationFactory` with **every** setting given explicitly

- Python test files have `Test*.cs` counterparts with the same case names, except

## House style

No comments and no XML docs in `src/` (Roslyn-enforced; `Migrations/` is generated and exempt), no
constant for a value used once. The why goes in this file.

## Uzcard and HUMO flows

Behaviour, states and reasons are the Python service's — read the "Uzcard flow", "Payment provider
boundary" and HUMO paragraphs of `../multipay/CLAUDE.md`. In short: `OTP_SENDING` /
`OTP_VERIFYING` reserve the external call before it is made; `PAYING` is claimed together with the
payment row (`BeginUzcardPay`); the recovery worker moves a `PAYING` session older than two
SV-GATE timeouts + 15 s (measured from the payment row's `created_at`) to `PENDING_CHECK` and only
then calls `trans.ext`; `trans.pay.purpose` is never repeated; `-207` is pending; a reverse is
`REVERSED` only after `trans.reverse` **and** `trans.ext` show the `ROK` row with the right
`refNum`; a `CREDITING`/`REVERSING` session untouched for the Operator timeout + two SV-GATE
timeouts + 15 s is handed to `NEEDS_MANUAL` without repeating any call. HUMO:
`card2 → sms2 → code2 → optional card → hold → Operator credit → confirm`, stale
`CREDITING`/`CONFIRMING` → `NEEDS_MANUAL`, `ReturnPayment` leaves `RETURNING`; `Cancel` names the
one state it expects (`HELD` or `CREDITING`), so a cancel decided on a `HELD` snapshot cannot
release a hold whose Operator credit has started.

SV-GATE/HUMO JSON values are compared with Python semantics (`Py.Str`, `Py.Int`, `Py.Truthy`,
`Py.CodeIn`): `str(resp) in {"0","00"}`, `str(None) == "None"`, `int("12")`, falsy `""`/`0`/`[]`.
This is what keeps the state machines identical for odd provider replies.

The HUMO SOAP envelopes are assembled by hand, byte-identical to ElementTree's output
(`ns0`/`ns1` prefixes, `<value />` for empty strings, only `& < >` escaped), proven against
`Fixtures/python_soap_envelopes.json`. Responses are parsed with DTD processing prohibited.

## Admin panel

`ADMIN_ENABLED` maps read-only Razor Pages under `/admin` (`Admin/`): sessions, payments, receipts,
SV-GATE and HUMO logs, with exactly the columns the starlette-admin views listed (`AdminViews.All`)
— no phone, token hash, card token or raw request/response. Times are stored UTC and shown in
UTC+05:00. `create`/`edit`/`delete`/`export`/`import` URLs answer 403; an unauthenticated request
gets `303 → /admin/login`; a wrong password or CSRF token gets 400.

The pages are styled with Tabler, the template starlette-admin is built on. The admin CSP allows
styles from `'self'` only, so `tabler.min.css` (v1.4.0, MIT) is vendored in `Admin/Statics/`,
embedded in the assembly and served at `/admin/statics/tabler.min.css` without login; no CDN and no
JavaScript. `/admin` is an overview (row counts per view, sessions grouped by status);
`AdminViews.Tone`/`Shape` decide which cells render as badges, ids or right-aligned numbers.

The login cookie (`multipay_admin_session`, `Path=/admin`, `HttpOnly`, `SameSite=Strict`, `Secure`
per `ADMIN_COOKIE_SECURE`, one hour) is `base64url(username).expiry.HMAC-SHA256(ADMIN_SECRET_KEY)`
rather than an ASP.NET authentication ticket: the Data Protection key ring is per-container, so a
ticket would die with every restart and fail across instances, while `ADMIN_SECRET_KEY` is already
the configured session secret (as in starlette's `SessionMiddleware`). The CSRF token is the HMAC of
a random nonce cookie. Credentials are compared in constant time. `/admin` is the only place a
cookie is ever set. `StarletteRoutingMiddleware` leaves `/admin` paths to Razor routing.

## Differences from the Python service

Translation decisions (intended):

| Python | .NET | Why |
|---|---|---|
| `inject()` static factories | constructor injection, `Program.cs` registrations | .NET has a container |
| FastAPI body models | `IRequestSchema<T>.Validate(JsonElement)` + model binders | pydantic's lax coercions and FastAPI's 422/400 split |
| `ContextVar` open claims | scoped `IdempotencyClaims` | `AsyncLocal` does not flow back to the caller |
| `get_utc_now()` monkeypatched | injected `TimeProvider`, `FakeTimeProvider` in tests | |
| Fernet for the HUMO PAN | AES-256-GCM (`PanCipher`), random 96-bit nonce, session key as associated data | no Fernet in .NET; the value lives only in Redis during one session and is never shared with Python, so format compatibility is not needed. Binding to the session key means a ciphertext copied to another session does not decrypt. |
| `HUMO_PAN_ENCRYPTION_KEY` = Fernet key | base64/base64url of exactly 32 bytes, checked at start-up | a Fernet key happens to satisfy this too |
| `DATABASE_URL` = SQLAlchemy URL | SQL Server connection string (same variable name) | |
| `SELECT … FOR UPDATE` | `WITH (UPDLOCK, ROWLOCK)` + `Adopt` | see Persistence |
| Postgres default collation | `Latin1_General_100_BIN2` on all strings | case-sensitive equality |
| Postgres MVCC | `READ_COMMITTED_SNAPSHOT ON` | non-blocking plain reads |
| 5 Alembic revisions | one initial EF migration | instructed; no production DB yet |
| rotating `payment.log.1..5` | Serilog `payment_001.log …` naming | Serilog's roller |
| `uvicorn.access` logger | `PaymentService.Access` middleware | same line format |
| `starlette-admin` | read-only Razor Pages behind `ADMIN_ENABLED` | see Admin panel |
| Swagger UI from FastAPI | `MapOpenApi("/api/openapi.json")` + the same CDN Swagger UI page at `/api/docs` | only with `DOCS_ENABLED` |

Deliberate deviations (behaviour differs from the Python code, on purpose):

- **`SECRET_KEYS` errors never print a kid.** The Python code names the kid in later messages
  ("secret of kid 'x'"); an entry without `kid:` whose secret is ≤32 safe characters parses as a
  kid, and the secret then lands in the start-up log. Here every message names the entry position,
  as the Python CLAUDE.md intends.
- **Only 2601/2627 become `ORDER_EXISTS`.** Python turns any `IntegrityError` (also CHECK/FK
  violations) into `ORDER_EXISTS`.
- **Exception text in logs is masked too**, not only the message.
- **A successful Uzcard `/resend` returns the session to `OTP_SENT`.** The Python `resend` leaves
  it in `OTP_SENDING` (HUMO's does not), so `verify` and `expire` answer `INVALID_STATE` and the
  customer can never pay after a resend. Confirmed against the Python service; fixed here on the
  user's decision and pinned by `The_frontend_handoff_shapes_hold_for_a_whole_flow`. The Python
  service still needs the same one-line fix.
- **Non-string `fullName`/`nameOnCard`** from a provider is stored as its Python `str()` instead of
  failing the insert (asyncpg would raise → 500).

Known gaps (behaviour differs, not worth the complexity, or not reachable in practice):

- Python's `json` accepts `NaN`/`Infinity` and UTF-16/32 bodies; System.Text.Json rejects them, so
  `{"hash": "x", "extra": NaN}` is 422 here and 401 in Python.
- FastAPI turns JSON nested deeper than Python's recursion limit into a 400; here the limit is 1000
  levels and deeper input is a 422.
- `str(float)` from provider replies follows Python's `repr` for the common cases (`1.0`, `1e+16`),
  not every corner of it.
- Header order differs (ASP.NET writes `Content-Type`/`Date` first); header names and values match,
  except that there is no `server: uvicorn` header.
- Outbound timeouts cover the whole exchange (one `CancellationTokenSource`); httpx applies the
  same number to connect, write and each read separately, so a slow-but-alive provider can succeed
  in Python and time out here (→ `PENDING_CHECK` / `NEEDS_MANUAL`, never a lost payment).
- Malformed provider shapes (`tokens: null`, a non-object row in `transactions`, an object as
  `error.code`) raise in Python (500, recovery picks the session up) and are skipped here.
- `svgate_log` transport errors carry .NET exception names (`TaskCanceledException`) where Python
  stores httpx's (`ReadTimeout`); a `null` body is logged as `{}`.
- If the client has gone when a request fails, the idempotency claims are still released but
  nothing is logged or written.
- Path edge cases: `Guid` binding accepts `(…)` and rejects `urn:uuid:…` (pydantic the reverse);
  `%2F` stays inside a segment; two `Idempotency-Key` headers are joined and refused; bodies over
  Kestrel's 30 MB limit and non-UTF-8 header bytes fail before the pipeline.
- `IConfiguration` also reads `ASPNETCORE_`-prefixed variables, so `ASPNETCORE_ENVIRONMENT` can fill
  a missing `ENVIRONMENT`.
- Admin: dates print the day without a leading zero, a bad CSRF token is 400 (starlette-admin: 403),
  search is case-sensitive (BIN2), the page size is fixed at 25, there are no detail pages and no
  `?next=` after login.
